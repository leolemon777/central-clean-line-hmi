## 2. 本次完成的 P11 内容

P11 是 Shell 内容承载区子页面，按用户给的 `E:\Users\29376\Desktop\P11_recipe_management_page.html` 风格实现。

核心能力：

- 左侧 Master 列表：搜索、分类筛选、配方状态徽章、锁定状态。
- 右侧 Detail 编辑区：标识区、操作按钮、Tab 导航、参数分组、底部保存状态。
- 参数集合完全由 JSON 驱动，不在 XAML 中硬编码具体参数项。
- Number / Enum / Boolean / String 参数按 `ParameterType` 动态切换输入控件。
- 锁定态只读；点击「解锁修改」弹出原因对话框。
- 解锁后修改参数会更新 DirtyCount 和底部状态。
- 数值参数实时校验 Min/Max，超范围红边 + Tooltip。
- 「保存为新版本」生成新 Recipe，例如 `v1.3 -> v1.4`，原版本保留。
- 「应用到生产」会二次确认；自动运行模式下不允许切换。
- `PROC_TOL` 根据 `IAlarmService.ActiveAlarms` 中的 `ALM-302` 标记注意态。
- 「版本历史 / 差异对比 / 备注」Tab 按要求只显示 `本功能在 v1.1 提供`。

## 4. 数据与持久化

配方 schema 样例：

- 源文件：`src\PipelineControl.UI\Resources\recipe-schema.sample.json`
- 输出目录：`src\PipelineControl.UI\bin\Debug\net8.0-windows\Resources\recipe-schema.sample.json`
- 运行时持久化：`%AppData%\PipelineControl\recipes.json`

首次运行时：

1. `MockRecipeService` 优先读 `%AppData%\PipelineControl\recipes.json`。
2. 不存在则读输出目录下的 `Resources\recipe-schema.sample.json`。
3. 然后写一份到 `%AppData%\PipelineControl\recipes.json`。

至少 5 个配方已在样例中：

- `A-Soft-02`：生效中，锁定。
- `A-Soft-03`：草稿。
- `B-Pure-01`：已锁。
- `B-Pure-02`：普通。
- `C-Clean-S`：普通。

注意：如果调试时看不到新 JSON 内容，先检查 `%AppData%\PipelineControl\recipes.json` 是否已有旧持久化文件；必要时备份后删除，让程序重新从 sample schema 初始化。

## 5. 最近修复的 exe 无法打开问题

用户后来指出：

`E:\Users\29376\Desktop\中央净软线\src\PipelineControl.UI\bin\Debug\net8.0-windows\PipelineControl.UI.exe` 无法打开。

已排查原因：

- exe 文件本体存在，不是缺少 exe。
- Windows 事件日志显示 `.NET Runtime` 未处理异常。
- 异常是 WPF `Run.Text` 绑定只读属性时被当作可回写绑定：
  - 典型错误：无法对 `AlarmRecord.SeverityText` 只读属性进行 TwoWay 或 OneWayToSource 绑定。
- 修复方式：
  - 全项目 XAML 中的展示型 `Run Text="{Binding ...}"` 显式加 `Mode=OneWay`。
  - 搜索框/参数输入/解锁原因/新建名称等 `TextBox` 输入保留 `Mode=TwoWay`。
  - 新增 `GlobalAlarmBannerSmokeTests` 复现并防回归。

当前实际启动状态：

- 新启动进程可打开主窗口，标题为 `中央净软线控制台`。
- 当前有效窗口进程示例：`PipelineControl.UI`，窗口标题不为空，`Responding=True`。
- 曾出现两个旧残留进程 `17860 / 22004`，无窗口标题且普通权限 `Stop-Process` 拒绝访问；它们不是本次新 exe 不能打开的原因。若新窗口继续处理，可先用任务管理器看是否还残留。
