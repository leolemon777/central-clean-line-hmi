# Postmortem:工控机手动输出无反应

> 表象是“连接上了、DLL 正常，但按手动按钮没反应”。
> 这类问题最容易误判成 DLL 或板卡问题，但实际更可能在 UI 输入语义、点动行为和触摸屏事件链。

## 现场表象

- 工控机部署包能启动。
- 板卡连接能成功。
- DLL 缺失问题已处理。
- 操作手动/点动按钮时，现场感觉“没有反应”。

## 初始判断

连接成功说明：

```text
DLL 加载基本正常
GA_Open / MC_Open 基本能走通
PC IP / 主卡 IP 至少没有完全配置错
```

所以第一怀疑对象不该是“DLL 全坏了”，而应转向：

```text
手动模式是否真的开启
点动输出是否被误解为点击保持
工控触摸屏事件是否没有进入 WPF Mouse/Touch 逻辑
输出写入失败是否只在状态栏弱提示
```

## 高概率原因

### 1. 手动模式小复选框反馈弱

原 UI 顶部是小 `CheckBox 手动`。在工控触摸屏上：

- 不容易点中
- 点中后反馈不明显
- 未开启时程序会拒绝输出

结果就是现场看起来“按钮没反应”。

### 2. 点动输出语义被误解

点动输出不是点击保持。

正确语义：

```text
按住按钮 -> ON
松开按钮 -> OFF
```

如果现场轻点一下，输出可能一闪即断，中间继电器或电磁阀未必有肉眼可见动作。

### 3. 工控触摸屏可能走 Stylus 事件

WPF 输入链里，工业触摸屏常见路径不止 Mouse：

```text
Mouse
Touch
Stylus
```

只处理 Mouse/Touch 时，部分触摸屏可能漏触发或行为不稳定。

## 已做修复

### UI 反馈增强

- `手动` 改成大号 ON/OFF 切换按钮。
- 2026-06-22 后，顶部 `手动 ON/OFF`、`连接`、`全部复位` 也增加 Touch/Stylus 兜底，避免触摸屏不触发普通 Click 时看起来“按钮没反应”。
- 开启后状态栏显示：

```text
手动模式已开启 · 点动按钮需按住输出，松开断开
```

### 点动按钮输入兜底

按钮事件覆盖：

```text
PreviewMouseLeftButtonDown / Up
LostMouseCapture
PreviewTouchDown / Up
LostTouchCapture
PreviewStylusDown / Up
LostStylusCapture
```

普通命令按钮也要覆盖：

```text
PreviewTouchDown / Up
PreviewStylusDown / Up
```

触摸抬起后主动执行绑定命令；ToggleButton 还要同步切换 IsChecked。

### 点动安全兜底

按下失败、不满足互锁、未开手动时，不进入 active jog 集合。

一旦进入 active jog 集合，松开或丢失捕获必须调用 OFF。

## 仍需现场确认

```text
[ ] 手动 ON/OFF 按钮在工控触摸屏上是否稳定切换
[ ] 点动按钮按住时 UI Y 点是否亮
[ ] 松手后 UI Y 点是否灭
[ ] 按住时中间继电器是否吸合
[ ] 松手后中间继电器是否断开
[ ] 线头电缸上升 Y0+Y1 是否同时动作
[ ] 线尾电缸上升 Y4+Y5 是否同时动作
[ ] 上升已按住时，下降是否被互锁拒绝
[ ] 写入失败时状态栏是否能看到错误信息
```

## 可复用教训

### 工控 UI 不要用弱反馈小控件控制危险模式

手动模式、自动模式、复位模式这类状态，不应该用小复选框。

应该用大号状态按钮，明确显示：

```text
手动 OFF
手动 ON
```

### 点动必须写清楚“按住输出”

按钮标题叫“点动输出”还不够，状态栏和 Tooltip 要明确：

```text
按住输出，松开断开
```

### WPF 工控触摸屏要同时兜 Mouse / Touch / Stylus

否则在开发电脑好用，在工控机触摸屏上可能像“按钮没反应”。
