## 总体评价

这个项目的方向是对的：把复杂业务页砍掉，只保留当前现场真正需要的 3 个入口。对于刚进入自动流程验证的产线，这比做一堆模拟数据页面更适合现场。

目前最有价值的部分是 **真实 IO 驱动 + 点位映射 + 手动点动输出 + 自动升降 v1** 已经形成闭环。它能让现场先验证接线、板卡、电源隔离、中间继电器、Y 点输出，再进入线头/线尾升降台自动逻辑验证。

最大风险也很清楚：**自动逻辑目前只接了线头/线尾升降台 v1，真实硬件上的限位、节拍、急停/气压/门禁等整线互锁仍要实测和补齐。**

一句话：**项目已经从 demo 走到现场 IO 验证和自动升降台验证阶段，但还没进入完整整线自动节拍阶段。**

## 做得好的地方

### 1. 运行入口收敛，避免假业务污染现场判断

项目已经删掉大屏、报警、配方、生产记录、日志查询、诊断维护等现阶段不需要的页面。当前只保留：

- 总控
- IO 点位
- 通讯

这让现场人员先聚焦“能不能连板卡、能不能读 X、能不能点 Y、动作组是否对”。

### 2. 点位映射集中在 JSON，不写死到 C#

`io-points.json` 是现场点位事实入口。X/Y 点名称、module、bit 后续都应该改这里，而不是散落到 ViewModel 或页面里。

这点非常重要，因为现场点位一定会变；硬编码会让后续维护变成找字符串。

### 3. 扩展卡1同步点做成动作组，而不是暴露单点误操作

扩展卡1有同步输出：

| 动作 | 点位 |
|------|------|
| 线头电缸上升 | Y0 + Y1 |
| 线头电缸下降 | Y2 + Y3 |
| 线尾电缸上升 | Y4 + Y5 |
| 线尾电缸下降 | Y6 + Y7 |
| 线头气缸伸出 | Y8，本体 X8 线头防呆光电 ON 时禁止 |
| 线尾气缸伸出 | Y9 |

UI 保留原始 Y 点显示，但 Y0-Y9 不允许绕过动作组单点操作。这是好设计，能避免现场误点单个同步点。

本体 X8 已改名为 `线头防呆光电`。X8 有信号时，扩展卡1 Y8 `线头气缸伸出` 不允许输出；如果 Y8 已经输出，输入刷新后会立即关掉，防止机构挤到。

### 4. 点动输出语义改对了

真正点动不是点击保持，而是：

```text
按下 ON
松开 OFF
丢失捕获 OFF
```

现在 Mouse / Touch / Stylus 都处理，适合工控触摸屏。这个经验可以复用到别的 WPF 工控 HMI。

### 5. 自动升降 v1 已接入，但范围很窄

`自动开启` 现在会持续控制线头、线尾两个升降台：

- 线头：X1 有信号上升到 X3 停，X1 无信号先等 3 秒再下降到 X2 停。
- 线尾：X5 有信号下降到 X6 停，X5 无信号先等 3 秒再上升到 X7 停。
- IO 控制卡本体 Y0/Y1：线头 X2 下限位有信号且 X1 行程无信号时 Y0 ON；Y1 同条件输出，但 X0 有信号时禁止输出；X1 行程一有信号时 Y0/Y1 都 OFF。
- IO 控制卡本体 Y2-Y9：自动开启后保持 ON，自动关闭或异常时 OFF。
- 扩展卡1 Y8/Y9：线头/线尾气缸按升降到位触发 3 秒脉冲；线头上升到 X3 上限后触发 Y8，线尾下降到 X6 下限后触发 Y9；线头 Y8 受本体 X8 线头防呆光电限制。
- 自动输出包含 IO 控制卡本体 Y0-Y9（pointNo 1-10，其中 Y0/Y1 为条件输出）和扩展卡1 Y0-Y9（pointNo 17-26，其中 Y8/Y9 为升降到位后触发的 3 秒脉冲）。
- 自动关闭只断开自动流程输出，不做整板 Reset。
- 30 秒不到位、上下限同时触发、通讯断开或输出写入失败会进入异常。

## 做得不好的地方 / 还要补

### 1. 工控机部署包现场验证仍不足

连接成功不代表输出链路全通。还需要逐项验证：

- DLL 是否全带齐
- VC++ runtime 是否齐
- 连接成功后读取 X 是否稳定
- 点动 Y 是否有实际输出
- 输出反馈是否能读回来
- 继电器和电磁阀电源是否隔离正确

之前“连接成功但手动无反应”就是现场验证暴露的问题。→ [[Postmortem 中央净软线-工控机手动输出无反应]]

### 2. IO 失败提示还不够现场化

目前写入失败主要在状态文本显示。现场可能看不到。后续应考虑：

- 写入失败红色状态条
- 当前动作按钮显示失败态
- 最近一次 IO 错误固定显示，不被普通状态覆盖
- 操作日志可导出给调试

### 3. 完整整线自动节拍尚未建模

目前只有升降台 v1，仍缺少完整整线工艺模型：

- 启动条件
- 步骤顺序
- 每步输出
- 每步等待 X 反馈
- 超时规则
- 停止与异常复位
- 安全互锁

后续不要直接在按钮事件里堆新动作，应该继续扩展当前状态机或拆出更明确的步骤执行器。

### 4. 部署和 Obsidian 同步还不是完全自动

因为当前 AI 会话写权限限制，Obsidian 文件先写在 `docs\obsidian\`，再同步到 `E:\Desktop\PLC知识库\中央净软线\`。后续最好让 Codex 工作区包含 Obsidian vault，减少复制问题。
