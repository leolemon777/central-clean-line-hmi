# 经验沉淀

> 铁规：每条记录必须回答“系统的哪一层失守了”，并写明对系统做了什么修改。
> 只修代码、不改系统的条目，视为未完成。
> 例外：纯执行失误且已有规则覆盖的，记录后标注“不加规则”，防止过度反应。

## 条目模板

### [日期] [任务 ID] <一句话现象>

- **现象**：
- **根因**：
- **失守层**（勾选）：
  - [ ] 任务卡含糊（In/Out of Scope 或验收没写清）
  - [ ] 验收缺失（Acceptance 有，但不可机械验证）
  - [ ] 上下文错误（给错文件 / 文档过时）
  - [ ] 缺停止规则
  - [ ] 工具权限缺失（MCP / API / 硬件 / 写操作未分级）
  - [ ] verify 盲区（该被机器拦下的没拦）
  - [ ] Review 盲区（diff 中的问题未被 checklist 拦下）
  - [ ] 纯执行失误（已有规则覆盖，Agent 没遵守）
- **系统修改**：写明改了哪个文件的哪一条；verify 盲区优先补 verify。
- **是否登记 rules-ledger**：是 / 否 / 不适用
