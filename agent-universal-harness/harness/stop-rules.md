# 停止规则

触发任意一条 -> 立即停止当前操作，输出状态报告：做到哪、为何停、需要什么决策。

每条长期规则必须在 `harness/rules-ledger.md` 登记起因。能转成 verify 自动检查的，优先转化为机器检查。

## 预授权原则

如果任务卡明确写出：

1. 要触碰的风险点；
2. 人类已确认计划；
3. 对应验收与回滚方案；

则该风险点在本任务范围内视为“已预授权”。未写清则按停止规则处理。

## 通用（所有层级）

| ID | 规则 |
|----|------|
| S1 | 连续 3 轮 verify 失败 |
| S2 | 需要修改任务卡 Out of Scope 的文件或行为 |
| S3 | 发现需求歧义、验收不可验证或任务卡自相矛盾 |
| S4 | 即将执行不可逆或难以恢复的操作：生产数据删除、数据迁移、覆盖历史、强制推送、批量删除等 |
| S5 | 涉及密钥、凭证、生产配置、真实内网地址 |

## L2+ 追加

`PROJECT.md` 风险声明勾选任意一项后启用：

| ID | 规则 |
|----|------|
| S6 | 涉及真实硬件、生产数据、资金、用户隐私、对外自动发送或外部写 API |
| S7 | 需要修改安全相关逻辑：鉴权、输入校验、急停、限位、联锁、权限边界等 |
| S8 | 需要新增第三方依赖、MCP Server、外部服务或长期运行进程 |
| S9 | 单轮 diff 超过任务卡 Size Check 或默认 400 行 |
